## Notes for the video and one-pager

- What the build demonstrates: one permission map, one mutation helper and one audit model reused by three thin tools; server-side denial of direct API calls; stale-write protection; linked counterparty→claim context; a registry for adding tools.
- What it does not show: Power Apps' maker experience for non-engineers, managed identity and governance, connectors, and environment and DLP policies. Those are the things the $250K actually buys and an owned build must replace or decide to drop.
- Honest framing: the initial prototype took about 11 wall-clock minutes after the scope was fixed. This does not mean ten production tools cost ten times 11 minutes. Recurring ownership (review, incidents, controls, upgrades) dominates; see research §5 for the capacity threshold (≈0.7–0.8 engineer-years/year at $250K fully avoidable spend).

## Refinement round

Samuel requested a separate refinement round; its timer ran from 2026-10-15T17:47:07Z to 2026-10-15T18:17:48Z (18:47:07 to 19:17:48 Europe/London), about 31 minutes. Together, the initial prototype and refinement took 42 wall-clock minutes. The Access Reviews spec was already written. Its 0.9-minute measurement, 17:48:17Z to 17:49:11Z, only covered applying that spec and is not used as build time. The change was 10 files changed, 205 insertions(+), 5 deletions(-).

The module guide omitted an explicit step for adding the module-specific demo account and its permissions and audit scope. That step is now in the README guide and app catalog. Access Reviews added `nina.access` and the `access_reviewer` role.

Rounds were timed from brief to last commit. Commits were batched, so per-commit timing is not meaningful. The delivery log records commit summaries and timestamps within each round; human time is not measured.

Final `.venv/bin/pytest -q`: `22 passed, 1 warning in 5.42s`. The warning is Starlette's `anyio.abc.BlockingPortal` deprecation. The first combined run had 13 failures: shared in-memory login throttling leaked across tests, the logout test followed its redirect before reading `Set-Cookie`, and one linkage assertion omitted a third seeded claim. The tests now isolate limiter state, inspect logout without redirects, and assert all three linked claims. The rerun passed.

`docker build -t ops-portal .` passed. Docker reported `JSONArgsRecommended`; the Dockerfile keeps the requested shell-form command so `${PORT:-8000}` expands. After deleting `data/portal.db`, `PORTAL_DB=data/portal.db .venv/bin/python -m app.seed --reset` recreated the database. Uvicorn was restarted on port 8000 and left running (shell `684563`). With a Nina session cookie, curl returned 200 for `/`, `/business-case`, `/delivery`, `/apps`, `/data`, `/access-reviews`, `/access-reviews/ENT-001`, `/counterparties`, `/counterparties/CP-001`, `/claims`, `/claims/CLM-1001`, `/flags`, `/audit` and `/api/metrics`. The first smoke pass exposed a missing f-string prefix in the flags list query; it was fixed, then pytest, Docker build and all page checks passed.
