# Demo cues and assessment coverage

These are preparation notes for the [five-minute Loom script](0.loom-script.md), not spoken material. The audience is the customer's VP of Engineering. Tie each feature to portfolio reuse, control, ownership or economics.

The UI reference is [PR 6](https://github.com/samuel-zhang01/Cognition-Take-Home-Assessment/pull/6) at 6b3747d: the three original tools are under Apps, Access reviews is under New apps, Security & controls is at /security, and + Add an app opens the combined Apps and delivery page. Use a preview or delivered version containing these changes. On the older main build, the catalog and delivery log are separate and the security summary page is absent.

## Recording method

Prepare short segments in the scripted order. Use Loom pause/resume for role changes and file selection, keeping the final recording below five minutes. The result is a narrated walkthrough, not a real-time speed benchmark. Keep the actual save, validation result or denial visible for each claimed demonstration.

Ordinary tabs in one browser profile share the login cookie. For different roles, use separate browser profiles or pause, sign out and sign in. For the stale-version example, two tabs with the same reviewer session are intentional: both must load the same starting record before the first save.

Use a disposable local recording database with fictional fixtures and pending records. Do not reuse a rehearsal's already-decided case or already-imported IDs. Prepare reason text before each action so typing does not consume the video. The demo account buttons fill usernames only; they do not sign in automatically.

## Timing

The 500 spoken words take about 222 seconds at 135 words per minute. The on-camera schedule totals 292 seconds, leaving about 70 seconds within the scenes for actions and breathing room, followed by an eight-second stop buffer. Speak while performing the short actions. Rehearse with the prepared state. The timing is a word-count estimate until Samuel records a read-through.

If a segment is slow, pause and prepare that same segment again. Preserve the feature's action/result and the final recommendation rather than adding narration. Do not spend the stop buffer on another topic.
