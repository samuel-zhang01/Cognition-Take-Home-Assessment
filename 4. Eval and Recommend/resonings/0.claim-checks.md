## Corrections that materially change the recommendation

The strongest challenge to the preferred staged exit is license overlap. A migrated app may save engineering time or improve a workflow while removing no Microsoft charge. That can still be worthwhile, but the justification is then the measured operational benefit. Dual operation, migration and historical evidence access must be costed.

The hybrid should earn its retained platform cost through concrete benefits: identity integration, connectors, governance, operator workflow or avoided migration. Strong existing ecosystem dependencies are one reason to retain it. A favorable total ownership comparison can also justify it. Code apps are not yet a demonstrated deployment target for the prototype's FastAPI server.

Maintenance needs an accepted owner, allocated capacity, monitoring, credential lifecycle, recovery and an escalation path. Automated PR analysis assists this work; it does not supply those arrangements. The [interview evidence](<../../1. Research/evidence/interview-insights.md>) strengthens the capacity, training and handover questions but does not verify this fintech's staffing or a Cognition service entitlement.

## Cost comparison assumptions

The three scenario rows in the draft reproduce the existing research using S = annual spend actually removed, B = one-time incremental transition cost and R = annual incremental ownership cost relative to keeping the platform:

- 3 × $250,000 − $100,000 − 3 × $100,000 = **+$350,000**.
- 3 × $250,000 − $200,000 − 3 × $200,000 = **−$50,000**.
- 3 × $100,000 − $100,000 − 3 × $100,000 = **−$100,000**.
- Delaying the first scenario's savings by a year while retaining three years of R gives 2 × $250,000 − $100,000 − 3 × $100,000 = **+$100,000**.

These scenarios assume flat annual amounts before tax and discounting. They are neither forecasts nor a maximum downside. Keep already-paid engineering capacity separate from new cash outlays, and avoid counting the same salary cost and a speculative value for its displaced work twice.

The $13.13 build charge is a separate observation, not an input that justifies the assumed annual costs. No per-tool cost or annual productivity factor is extrapolated from it.

Current public Premium pricing is $20/user/month under annual billing. The announced $22 rate applies to relevant terms beginning from 1 January 2027; only affected SKUs change. Retain actual contract and renewal dates when moving beyond the flat scenarios. [Microsoft price announcement](https://www.microsoft.com/en-us/licensing/news/power-apps-premium-price-update)

Devin pricing still contains a conflict: its pricing card describes an $80 team charge plus $40/full seat, while billing documentation describes an $80 minimum with seats counted toward it. Do not use either interpretation as a confirmed quote. Confirm the applicable plan, security requirements and usage charges. [Pricing](https://devin.ai/pricing), [billing mechanics](https://docs.devin.ai/admin/billing/self-serve)

## Development data and security

The public Platform Terms section 4.2 restrict listed sensitive personal inputs, including KYC and financial fields. Enterprise section 4.3 permits certain processing only through a separate written agreement with safeguards. Synthetic development fixtures avoid assuming permission to submit real records. Independently hosted production code and data exposed to the development agent have different boundaries. [Platform Terms](https://cognition.com/legal/platform-terms-of-service), [Enterprise agreement](https://cognition.com/legal/enterprise-terms-of-service)

Security profiles can constrain repository, network and tool access; available controls and enforcement depend on configuration and plan. Restricting participation by job title alone is not an adequate security model. User requests, code changes, releases and operational approvals should have distinct authority.
